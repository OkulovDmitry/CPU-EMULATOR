# Виртуальная машина: симулятор процессора

Проект посвящён написанию собственной виртуальной машины, которая симулирует работу процессора. Он состоит из трёх программ: ассемблера, дизассемблера и машины.

## Возможности

| Программа | Назначение |
| :--- | :--- |
| Ассемблер | Переводит программу на языке ассемблера в байт-код |
| Дизассемблер | Восстанавливает текст ассемблерной программы из байт-кода |
| Виртуальная машина | Исполняет байт-код (стековый процессор) |
| Декодер и hex-dump | Декодер азбивает файл побитово, выводит расшифровку - в конкретных 64 битах записана команда или аргумент, выводит флаги команды и тип числа в аргументе. Hex-dump выводит двоичный файл в шестнадцатеричном виде с адресамии ASCII-колонкой.

## Сборка и запуск

<details>
<summary>Подробное описание возможностей программы на этапе сборки и запуска</summary>

### Требования

- `gcc` и `make`
- Linux, WSL или macOS. Сборка использует AddressSanitizer и UBSan (`-fsanitize`). В Windows без WSL они обычно недоступны, в этом случае см. раздел «Сборка без санитайзеров».

### Сборка

Все команды выполняются из папки проекта: `make` ищет `Makefile` только в текущей папке.

```bash
cd путь/к/проекту
make
```

После сборки в папке появляются четыре программы:

| Программа | Назначение |
| :--- | :--- |
| `asm` | ассемблер: текст программы в байт-код |
| `cpu` | машина: исполняет байт-код |
| `disasm` | дизассемблер: байт-код в текст |
| `decoder` | показывает содержимое байт-кода по ячейкам и битам |

Цели `make`:

| Команда | Что делает |
| :--- | :--- |
| `make` | собирает все четыре программы |
| `make asm`, `make cpu`, `make disasm`, `make decoder` | собирает одну программу |
| `make test` | собирает всё и запускает тесты |
| `make clean` | удаляет программы, `.o`, `.d`, все `*.bin` и `output.txt` |
| `make -n` | показывает команды, ничего не выполняя |
| `make -B` | пересобирает всё принудительно |

Пересборка идёт только для изменённых файлов, правка заголовка пересобирает все файлы, которые его подключают. Если изменил структуру в `.h` и поведение странное, выполни `make clean && make`.

### Запуск

Программы запускаются с `./` из папки проекта.

```bash
./asm     input.txt      program.bin     # текст -> байт-код
./cpu     program.bin                    # исполнение
./disasm  program.bin    restored.txt    # байт-код -> текст
./decoder program.bin    decoded.txt     # таблица ячеек с расшифровкой
./decoder -hex program.bin dump.txt      # hex-дамп файла с ASCII-колонкой
```

| Программа | Аргументы |
| :--- | :--- |
| `asm` | `<text_in> <bytecode_out>` |
| `cpu` | `<bytecode_in>` |
| `disasm` | `<bytecode_in> <text_out>` |
| `decoder` | `[-hex] <bytecode_in> <text_out>` |

Расширение файла байт-кода может быть любым, в проекте используется `.bin`. Байт-код бинарный, открывать его текстовым редактором бесполезно, для этого есть `decoder`.  

Код возврата `0` при успехе и `1` при ошибке. Сообщения об ошибках идут в `stderr` в виде `файл:строка: текст`. При ошибке ассемблера выходной файл не создаётся.

### Пример

Программа `count.txt`, обратный отсчёт:

```asm
        PUSH 3
        POP AX
loop:
        PUSH AX
        OUT
        PUSH AX
        PUSH 1
        SUB
        POP AX
        PUSH AX
        PUSH 0
        JNE loop
        HLT
```

```bash
./asm count.txt count.bin
./cpu count.bin
```

Вывод:

```text
3
2
1
```

### Тесты

```bash
make test
```

Для каждого файла из списка `TESTS` (в `Makefile`) выполняется цепочка:

```text
asm -> cpu -> disasm -> asm -> cmp
```

Байт-код, собранный из исходного текста, сравнивается с байт-кодом, собранным из текста дизассемблера. Тест проходит, если файлы побайтно совпали. Вывод `cpu` при этом печатается, но с эталоном не сравнивается.

Что нужно знать:

- Тесты запускаются из корня проекта. Файл `input.txt` должен лежать в корне, остальные тестовые программы лежат в папке `tests/`.
- Папка `tests/` входит в репозиторий. Можно создать её самому: `mkdir tests`.
- Чтобы добавить тест, положи программу в `tests/` и допиши путь в `Makefile`:

  ```make
  TESTS = input.txt tests/loop.txt tests/call.txt
  ```

  Или подключи все файлы папки автоматически: `TESTS = $(wildcard tests/*.txt)`.
- Тестовая программа должна завершаться командой `HLT`. Бесконечный цикл повесит `make test`.
- Во время теста в текущей папке создаются `byte_code.bin`, `byte_code2.bin` и `output.txt`. Команда `make clean` удаляет все `*.bin` и `output.txt`, поэтому не храни под такими именами свои файлы.

### Декодер

`decoder` показывает байт-код так, как его видит машина.

**Режим по умолчанию** строит таблицу ячеек:

```bash
./decoder program.bin decoded.txt
```

Первая строка файла содержит заголовок: сигнатуру, версию и количество ячеек. Дальше идёт по строке на каждую ячейку:

| Колонка | Содержимое |
| :--- | :--- |
| номер | индекс ячейки в массиве |
| биты | 64 бита ячейки, сгруппированные по 8 |
| значение | шестнадцатеричная и десятичная запись |
| пояснение | что это за ячейка |

Пояснение зависит от того, чем является ячейка:

| Пояснение | Значение |
| :--- | :--- |
| `command PUSH IMM FLT` | ячейка команды, после названия перечислены флаги |
| `register AX` | операнд-регистр |
| `memory cell, its number is in register AX` | адрес ячейки памяти лежит в регистре |
| `memory cell number 5` | адрес ячейки памяти задан числом |
| `number 0.5 (double, ...)` | число, в ячейке лежат биты `double` |
| `jump to cell 4` | адрес перехода |
| `integer 7` | целое число |
| `BAD ...` | некорректная ячейка |

**Режим `-hex`** выводит весь файл в шестнадцатеричном виде:

```bash
./decoder -hex program.bin dump.txt
```

В строке 16 байт: смещение, байты по два символа и справа текстовое представление.

### Сборка без санитайзеров

Санитайзеры замедляют программу и увеличивают потребление памяти. Для обычного запуска их можно отключить, переопределив переменные из командной строки:

```bash
make clean
make CFLAGS="-O2 -Wall -Wextra -MMD -MP" LDFLAGS=
```

При переходе между режимами всегда выполняй `make clean`, иначе в папке останутся объектные файлы старого режима.

### Добавление файлов в сборку

Новый `.c` файл нужно указать в `Makefile`. Если он нужен всем программам, допиши объектный файл в `COMMON`, иначе только в список нужной программы (`ASM_OBJ`, `CPU_OBJ`, `DIS_OBJ`, `DEC_OBJ`):

```make
COMMON  = bytecode.o isa.o stack.o новый_модуль.o
```

Правила компиляции `.c` в `.o` и зависимости от заголовков добавлять не нужно, они общие.

#### Теоретическая справка и разбор моего Makefile: зачем и основнные возможности

##### Общая картина
Makefile описывает граф зависимостей: что из чего получается и какой командой. При запуске make, он берёт первую цель в файле(в текущем all, строка 11) и рекурсивно проверяет, всё ли актуально. Файл считается устаревшим, если он отсутствует или какая-то из зависимостей изменилась. Устаревшее пересобирается, остальное пропускается.
Для cpu граф выглядит так:
```text
cpu_main.c ---> cpu_main.o --|
cpu.c      ---> cpu.o      --|
bytecode.c ---> bytecode.o ----- линковка ---> cpu
isa.c      ---> isa.o      --|
stack.c    ---> stack.o    --|
```
Каждая стрелка `.c` в `.o` это правило из строки 25, а стрелка в cpu это правило из строки 16.

##### Строки 1-3: переменные
```make
CC      = gcc
CFLAGS  = -Wall -Wextra -Wshadow -g -fsanitize=address,undefined -MMD -MP
LDFLAGS = -fsanitize=address,undefined
```
Переменные нужны чтобы менять настройки в одном месте. Обращение к ним пишется через `$(CC)`, `$(CFLAGS)`.
| Флаг | Что делает |
| :--- | :--- |
| `-Wall -Wextra` | Включает основные предупреждения компилятора |
| `-Wshadow` | Предупреждает, когда локальная переменная перекрывает другую с тем же именем |
| `-g` | Кладёт в программу отладочную информацию (номера строк для отчётов санитайзера и dgb) |
| `-fsanitize=address,undefined` | вставляет проверки: выход за границы памяти, использование после `free`, утечки, неопределённое поведение |
| `-MMD -MP` | при компиляции записывает список заголовков в `.d`-файл(подробнее см. ниже) |

`CFLAGS` относится к компиляции (`.c` и `.o`), а `LDFLAGS` к линковке. Санитайзер нужен в обоих местах: при компиляции вставляются проверки, при линковке подключается библиотека. При забывании одного из двух получим `undefined reference to __asan_...`.

##### Строки 5-9: списки обЪектных файлов
```make
COMMON  = bytecode.o     isa.o       stack.o
ASM_OBJ = asm_main.o                 $(COMMON)
DIS_OBJ = disasm_main.o              $(COMMON)
CPU_OBJ = cpu_main.o     cpu.o       $(COMMON)
DEC_OBJ = decoder_main.o             $(COMMON)
```
`COMMON` это то, что нужно всем программа, остальные списки добавляют к нему свои файлы. Пробелы для выравнивания `make` игнорирует. Благодаря такой записи общий модуль  компилируется один раз, а линкуется в каждую программу.

##### Строки 11-22 : цели-программы
```make
all: asm cpu disasm decoder

asm:    $(ASM_OBJ)
	$(CC) $(LDFLAGS)   $^ -o $@
```

`all` стоит первым, поэтому  просто `make` собирает все четыре программы. У него нет команды: он существует ради зависимостей.  
В правиле `asm` команда после раскрытия переменных превращается в:
```text
gcc -fsanitize=address,undefined  asm_main.o bytecode.o isa.o stack.o  -o asm
```
Автоматические переменные внутри команд:
| Переменная | Значение |
| :--- | :--- |
| `$@` | имя цели(asm) |
| `$^` | все зависимости |
| `$<` | первая зависимость |

В правиле  для `cpu` в конце стоит `-lm`: это подключаение автоматической математической библиотеки (`fabs` из `cpu.c`). Флаг идёт после обЪектных файлов, потому что линковщик берёт из библиотеки только то, что уже кому то понадобилось. Остальным программам `-lm` не нужен.

##### Строки 25-26: шабллонное правило
```make
%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@
```
Читается так: любой `X.o` получается из `X.c` командой `gcc ... -c X.c -o X.o`. Флаг `-c`  означает "скомпилирровать но не линковать". Одно правило заменяет пять отдельных, и именно  оно реализует раздельную компиляцию: каждый `.c` компилируется независимо, а `make` решает, какие `.o` ещё актуальны.

##### Строка 28: зависимости от заголовков
```make
-include $(wildcard *.d)
```
Без неё `make` знал бы, что `cpu.o` заивисит от `cpu.c`, но не знал бы про `cpu.h` и `isa.h`. Правка заголовка не вызвала бы пересборки, и в программе остались бы объектные файлы со старыми структурами.  
Решение составляют два флага  из `CFFLAGS`:  
1. **-MMD** - заставляет gcc при компиляции `cpu.c` записать файл `cpu.d` примерно такого вида: `cpu.o`: `cpu.c` `cpu.h` `isa.h` `stack.h`. Системные заголовки в список не попадают.  
2. **-MP**  - добавляет к каждому заголовку пустое правило. Без него удаление или переименование заголовка ломает сборку сообщением `No rule to make target 'old.h'`.  

А `-include` подтягивает все эти `.d` в Makefile. Дефис в начале  значит "не ругаться, если файлов нет": при первой сборке `.d` еще нет. Эта строка стоит ниже `all`, поэтому не меняет цель по умолчанию: ею остаётся первая цель в файле.

##### Строки 30-39: тесты
```make
TESTS = tests/input.txt tests/call.txt

test: all
	@for t in $(TESTS); do \
	    echo "== $$t"; \
	    ./asm $$t byte_code.bin && ./cpu byte_code.bin && \
	    ./disasm byte_code.bin output.txt && ./asm output.txt byte_code2.bin && \
	    cmp byte_code.bin byte_code2.bin || exit 1; \
	done
	@echo "ROUNDTRIP OK"
```

По частям:
1. **test: all** перед тестом всё пересобирается, чтобы не запустить устаревшие бинарники.  
2. **@** в начале строки подавляет вывод самой команды, видно только её результат.  
3. **$$t** это `$t` для оболочки. Один `$` забрал бы сам make, поэтому в Makefile доллар для shell пишется дважды.  
4. Цепочка `&&` останавливается на первой упавшей программе, `|| exit 1` тогда прерывает цикл с ошибкой, и `make` печатает `Error 1`. Строка `ROUNDTRIP OK` до этого момента не доходит.  
5. `cmp` сравнивает два бинарных файла побайтно и возвращает 0, только если они идентичны (для бинарных файлов вместо `diff`).  
 Схема одной итерации такая:
 ```text
t.txt --asm---> byte_code.bin ---cpu---> вывод на экран
                    |
                    |---disasm---> output.txt ---asm---> byte_code2.bin
                    
                    cmp byte_code.bin byte_code2.bin
 ```

 ##### Строки 41-44: уборка и `.PHONY`
 ```make
 clean:
	rm -f asm cpu disasm decoder *.o *.d *.bin output.txt

.PHONY: all test clean
 ```
 `rm -` не ругается на отсутствующие файлы. `.PHONY` сообщает `make`, что `all`, `test` и `clean` это команды, а не файлы: их нужно выполнять всегда, даже если в папке появится файл с таким именем.

### `isa.h / .c`

Instruction Set Architecture: описание того, что умеет делать процессор. Задаёт его команды, регистры и способ обращения к ним.

<details>
<summary>Подробнее про ISA</summary>

#### Таблица команд

Для трансляции ассемблерного кода во внутреннее представление процессора используется массив `isa`. Он связывает текстовые мнемоники команд с их внутренними идентификаторами (Opcodes) и поддерживаемыми типами аргументов. (isa - массив структур CommandInfo - в этой структуре хранится название команды, разрешенные флаги, а также отдельный флаг - is_jump, который определяет может ли команда принимать в качестве аргумента метки)

| Идентификатор (Opcode) | Мнемоника | Аргументы (флаги типов) | Метки | Описание команды |
| :--- | :--- | :--- | :---: | :--- |
| `CMD_HLT` | `HLT` | `0` | `0` | Остановка процессора, завершение программы. |
| `CMD_PUSH` | `PUSH` | `BIT_IMM \| BIT_REG \| BIT_FLT \| BIT_MEM` | `0` | Положить значение (число, регистр или ячейку памяти) на вершину стека. |
| `CMD_ADD` | `ADD` | `0` | `0` | Сложение. |
| `CMD_SUB` | `SUB` | `0` | `0` | Вычитание. |
| `CMD_MUL` | `MUL` | `0` | `0` | Умножение. |
| `CMD_DIV` | `DIV` | `0` | `0` | Деление. |
| `CMD_OUT` | `OUT` | `0` | `0` | Вывод значения в консоль. |
| `CMD_POP` | `POP` | `BIT_REG \| BIT_IMM \| BIT_MEM` | `0` | Снять значение со стека и записать в регистр или в ячейку памяти. |
| `CMD_JMP` | `JMP` | `BIT_IMM` | `1` | Безусловный переход по адресу (метке). |
| `CMD_JA` / `CMD_JAE` | `JA` / `JAE` | `BIT_IMM` | `1` | Условные переходы: выше / выше или равно. |
| `CMD_JB` / `CMD_JBE` | `JB` / `JBE` | `BIT_IMM` | `1` | Условные переходы: ниже / ниже или равно. |
| `CMD_JE` / `CMD_JNE` | `JE` / `JNE` | `BIT_IMM` | `1` | Условные переходы: равно / не равно. |
| `CMD_CALL` | `CALL` | `BIT_IMM` | `1` | Вызов подпрограммы, адрес возврата сохраняется. |
| `CMD_RET` | `RET` | `0` | `0` | Возврат из подпрограммы. |
| `CMD_DRAW` | `DRAW` | `0` | `0` | Рисование картинок |

Условные переходы снимают со стека два значения: `top` (вершина) и `below` (предпоследнее). Переход выполняется, если `below <op> top`, где `<op>` зависит от команды. Например, `JA` прыгает при `below > top`.  

Имена регистров задаются массивом `reg_names`.  

Также задается одна ячейка байт-кода - code_t (uint64_t).  

Операнд в квадратных скобках обращается к памяти. `PUSH [4]` кладёт на стек значение ячейки 4, `POP [4]` снимает значение со стека и записывает его в ячейку 4. Номер ячейки может лежать в регистре: `PUSH [AX]`. Номер ячейки всегда целый, а значения в ячейках могут быть дробными. Память процессора состоит из `VRAM_SIZE` ячеек (16 на 16), обращение за её границы считается ошибкой.

#### Макросы ISA

| Макрос | Значение | Назначение |
| :--- | :--- | :--- |
| `REG_COUNT` | `4` | Количество регистров процессора |
| `CMD_MASK` | `0x1F` | Младшие 5 бит: номер команды |
| `BIT_IMM` | `1 << 5` | Флаг константы (числа) в байт-коде |
| `BIT_REG` | `1 << 6` | Флаг номера регистра в байт-коде |
| `BIT_MEM` | `1 << 7` | Флаг обращения к памяти |
| `BIT_FLT` | `1 << 8` | Флаг числа с плавающей точкой: константа хранит биты `double` |
| `CELL_OP(cell)` | `((cell) & (CMD_MASK))` | Код операции из ячейки |
| `CELL_FLAGS(cell)` | `((cell) & ~(CMD_MASK))` | Флаги из ячейки |

#### Теоретическая справка: битовые маски и упаковка данных

Ячейка байт-кода (`code_t`) занимает 64 бита, а номер команды умещается в 5 из них (всего возможно 32 команды). 64 бита это ровно размер `double`, поэтому дробное число лежит в ячейке без преобразований. Чтобы не тратить ячейку только на код команды, в одно число упаковываются и код команды, и флаги её аргументов.

Устройство ячейки:

```text
 Бит:   63 ................. 9    8   7   6   5   4   3   2   1   0
       [    Не используется    ] [F] [M] [R] [I] [   Код команды   ]
                                  |   |   |   |       (Opcode)
                                  |   |   |   +-- BIT_IMM (число)
                                  |   |   +------ BIT_REG (регистр)
                                  |   +---------- BIT_MEM (память)
                                  +-------------- BIT_FLT (биты double)
```

##### 1. Побитовый сдвиг влево (`<<`): создание флагов

Флаги в `isa.h` задаются оператором сдвига. Выражение `(1 << 5)` берёт единицу (`00000001`) и сдвигает её влево на 5 позиций:  

- `BIT_IMM = (1 << 5)` даёт `00100000` (`0x20`)
- `BIT_REG = (1 << 6)` даёт `01000000` (`0x40`)
- `BIT_MEM = (1 << 7)` даёт `10000000` (`0x80`)
- `BIT_FLT = (1 << 8)` даёт `100000000` (`0x100`)

Каждый флаг занимает ровно один свой бит, поэтому флаги не пересекаются и их можно комбинировать побитовым ИЛИ (`|`): `BIT_IMM | BIT_REG`.

##### 2. Побитовое И (`&`): выделение операции (`CELL_OP`)

Чтобы узнать, какую команду выполнять, нужно отрезать флаги и оставить только младшие 5 бит. Для этого применяется маска `CMD_MASK = 0x1F` (`00011111`).  

Операция `&` работает как фильтр: единица остаётся только там, где она есть у обоих чисел.  

```text
Ячейка:          01000101   (команда CMD_DIV с флагом BIT_REG)
Маска CMD_MASK:  00011111   (фильтр младших 5 бит)
------------------------
Результат (&):   00000101   (5, код команды CMD_DIV)
```

Это делает макрос `CELL_OP(cell)`: он зануляет верхние биты и оставляет чистый код операции.

##### 3. Побитовое НЕ (`~`): выделение флагов (`CELL_FLAGS`)

Чтобы, наоборот, отбросить команду и получить только флаги, маску инвертируют. Оператор `~` переворачивает все биты: `~CMD_MASK` превращает `00011111` в `11100000`.

```text
Ячейка:           01000101   (команда CMD_DIV с флагом BIT_REG)
Инверсия (~MASK): 11100000   (фильтр флагов)
-------------------------
Результат (&):    01000000   (остался только флаг BIT_REG)
```

Это делает макрос `CELL_FLAGS(cell)`. Проверка `if (CELL_FLAGS(cell) & BIT_REG)` показывает процессору, что дальше нужно читать номер регистра.

#### Разбор функции assembler()

`assembler()` возвращает указатель на начало массива с ячейками `code_t`, принимает имя `path` файла, который мы читаем и `int* size` - указатель на размер байт-кода, который мы прочитаем из файла.

```code
code_t* assembler(const char* path, int* size)
```
| Имя | Значение |
| :--- | :--- |
| `in` | читаемый файл с именем `path` |
| `capacity` | первоначальный размер байт-кода |
| `bytecode` | массив указателей на ячейки `code_t` байт-кода |
| `labels` | таблица меток, изначально пустая |
| `count` | количество команд и аргументов в `bytecode` |
| `pass` | номер прохода ассемблера

```code
FILE* in = fopen(path, "r");
    if (in == NULL)
    {
        perror(path);
        return NULL;
    }

    int capacity = 64;                                                    // первоначальный размер байт-кода
    code_t* bytecode = malloc(capacity * sizeof(code_t));
    if (bytecode == NULL)
    {
        fclose(in);
        fprintf(stderr, "bytecode out of memory in file %s\n", path);
        return NULL;
    }

    LabelTable labels = { .labels_count = 0 };
    int count         = 0;                      // количество команд и аргументов в bytecode
```

В цикле `for` реализуются 2 прохода по входному файлу `in`.

| имя | значение |
| `lineno` | номер текущей строки в файле |
| `line[]` | текущая строка |

В цикле `while`, который на каждом новом шагу читает новую строку входящего файла `in`, первым делом производится изменение строки:
Обрезка комментариев:
```code
char* comment = strchr(line, ';');
if (comment != NULL) *comment = '\0';                    //обрезка комментариев
```
| имя | значение |
| `used` | в `sscanf()` через `%n` ей присваивается количество прочитанных символов |
| `word` | первое слово в строке `line` |
Пропуск пустых строк или строк-комментариев:
```code
int used = 0;
char word[64] = "POISON";

if (sscanf(line, "%63s%n", word, &used) != 1) continue;  // пропускаем пустые строки
```
Далее определяем есть ли в конце `word` двоеточие и если да, то далее происходит следующая обработка метки:
Проверка валидности имени метки:
```code
word[strlen(word) - 1] = '\0';

if (!(label_name_ok(word)))
{
    fprintf(stderr, "%s:%d: bad label name '%s'\n", path, lineno, word);
    free(bytecode);
    fclose(in);
    return NULL;
}
```
Если метки еще не существует и проход первый, то происходит запись метки в массив меток:
```code
if (pass == 1 && !(label_add(&labels, word, count)))
{
    fprintf(stderr, "%s:%d: duplicate or too long label '%s'\n", path, lineno, word);
    free(bytecode);
    fclose(in);
    return NULL;
}
```
Далее происходит проверка на мусор после метки, `end_of_label` - указатель на конец метки, далее пропускаются пробелы и если указатель указывает не на `\0` или `\n`, происходит запись ошибки:
```code
char* end_of_label = line + used;
while (isspace((unsigned char)*end_of_label)) end_of_label++;
if (*end_of_label  != '\0' && *end_of_label != '\n')
{
    fprintf(stderr, "%s:%d: unexpected '%s' after label\n", path, lineno, end_of_label);
    free(bytecode);
    fclose(in);
    return NULL;
}
```

Если же слово в строке не было меткой, значит это была команда и теперь произодится обработка команды:
`op` - опкод команды
```code
int op = find_command(word);
if (op == -1)
{
    fprintf(stderr, "%s:%d: unknown command '%s'\n", path, lineno, word);
    free(bytecode);
    fclose(in);
    return NULL;
}
```
Далее идет проверка, что в `bytecode` еще влезает команда с аргументами и его расширение, если нет:
```code
if (count + 3 > capacity)
{
    code_t* bytecode_tmp = realloc(bytecode, 2 * capacity * sizeof(code_t));
    if (bytecode_tmp == NULL)
    {
        free(bytecode);
        fclose(in);
        fprintf(stderr, "bytecode out of memory in file %s\n", path);
        return NULL;
    }
    capacity *= 2;
    bytecode = bytecode_tmp;
}
```
Теперь `flags` - флаги команды `op`, а `operand` - ее возможный аргумент, сейчас еще не заполнены.
```code
int flags   = 0;
code_t operand = 0;
```
Далее если из isa определяется принимает ли команда аргументы и если да происходит обработка аргументов:
```code
char  arg_text[64];
int   arg_used     = 0;

if (sscanf(line + used, "%63s %n", arg_text, &arg_used) != 1)
{
    fprintf(stderr, "%s:%d: missing argument for %s\n", path, lineno, word);
    free(bytecode);
    fclose(in);
    return NULL;
}
```
