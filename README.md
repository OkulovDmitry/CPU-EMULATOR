Для трансляции ассемблерного кода во внутреннее представление процессора используется массив 'isa'. Он связывает текстовые **мнемоники** команд с их **внутренними идентификаторами (Opcodes)** и поддерживаемыми **типами аргументов**.

| Идентификатор (Opcode) | Мнемоника | Аргументы (Флаги типов) | Поддержка меток(labels) | Описание команды |
| :--- | :--- | :--- | :--- | :--- |
| `CMD_HLT` | `"HLT"` | `0` | `0` | Остановка процессора / завершение программы. |
| `CMD_PUSH` | `"PUSH"` | `BIT_IMM \| BIT_REG` | `0` | Положить значение (число или регистр) на вершину стека. |
| `CMD_ADD` | `"ADD"` | `0` | `0` | Сложение (работает со стеком). |
| `CMD_SUB` | `"SUB"` | `0` | `0` | Вычитание. |
| `CMD_MUL` | `"MUL"` | `0` | `0` | Умножение. |
| `CMD_DIV` | `"DIV"` | `0` | `0` | Деление. |
| `CMD_OUT` | `"OUT"` | `0` | `0` | Вывод значения в консоль. |
| `CMD_POP` | `"POP"` | `BIT_REG` | `0` | Извлечь значение со стека в регистр. |
| `CMD_JMP` | `"JMP"` | `BIT_IMM` | `1` | Безусловный переход по адресу (метке). |
| `CMD_JA` / `CMD_JAE` | `"JA"` / `"JAE"` | `BIT_IMM` | `1` | Условные переходы: Выше (Above) / Выше или равно. |
| `CMD_JB` / `CMD_JBE` | `"JB"` / `"JBE"` | `BIT_IMM` | `1` | Условные переходы: Ниже (Below) / Ниже или равно. |
| `CMD_JE` / `CMD_JNE` | `"JE"` / `"JNE"` | `BIT_IMM` | `1` | Условные переходы: Равно (Equal) / Не равно. |
| `CMD_CALL` | `"CALL"` | `BIT_IMM` | `1` | Вызов подпрограммы (переход с сохранением адреса возврата). |
| `CMD_RET` | `"RET"` | `0` | `0` | Возврат из подпрограммы. |

> **Нюансы команд**
> * **Условные переходы** ('CMD_J...') - условие выглядит следующим образом: **'below cmp_func(<, >, ...) top'**

Для определения имен регистров используется массив 'reg_names'.

> **Макросы isa**
> * **REG_COUNT = 4**      задает количество регистров процессора
> * **CMD_MASK  = 0x1F**   определяет младшие 5 бит как номер команды
> * **BIT_IMM   = 1 << 5** Флаг на константу (число) в байт-коде
> * **BIT_REG   = 1 << 6** Флаг на номер регистра в байт-коде
> * **BIT_MEM   = 1 << 7**
> * **CELL_OPP(cell)   = ((cell) & (CMD_MASK))**  возвращает ячейку операции
> * **CELL_FLAGS(cell) = ((cell) & ~(CMD_MASK))** возвращает ячейку флагов

### Теоретическая справка: Битовые маски и упаковка данных

Поскольку ячейка байт-кода (`code_t`) имеет размер 32 бита, хранить в ней только код команды (который занимает всего от 0 до 15) неэффективно. Проект использует технику **упаковки данных**, где в одно 32-битное число «зашиваются» и код команды, и флаги её аргументов.

Вот как устроена наша ячейка изнутри на бинарном уровне:

```text
 Бит:  31 ........................ 8   7   6   5   4   3   2   1   0
       [    Не используется      ] [M] [R] [I] [   Код команды   ]

                                    |   |   |        (Opcode)
                                    |   |   +-- BIT_IMM (Число)
                                    |   +------ BIT_REG (Регистр)
                                    +---------- BIT_MEM (Память)
```

#### 1. Побитовый сдвиг влево (`<<`) — Создание флагов
Флаги в `isa.h` задаются с помощью оператора сдвига `<<`. Выражение `(1 << 5)` берет единицу в двоичном виде (`00000001`) и сдвигает её влево на 5 позиций.
*   `BIT_IMM = (1 << 5)` превращается в `00100000` в двоичной системе (или `0x20` в 16-ричной).
*   `BIT_REG = (1 << 6)` превращается в `01000000` (`0x40`).
*   `BIT_MEM = (1 << 7)` превращается в `10000000` (`0x80`).

Благодаря этому каждый флаг занимает **ровно один свой бит** и они никогда не пересекаются между собой. Их можно комбинировать с помощью побитового ИЛИ (`|`): `BIT_IMM | BIT_REG`.

---

#### 2. Побитовое И (`&`) — Выделение операции (Макрос `CELL_OP`)
Чтобы процессор узнал, какую именно команду ему выполнять, ему нужно «отрезать» флаги аргументов и посмотреть только на младшие 5 бит. Для этого применяется маска `CMD_MASK = 0x1F` (в двоичном виде это `00011111`).

Операция **Побитового И (`&`)** работает как фильтр: она оставляет `1` только там, где у обоих чисел были единицы.

```text
Пример ячейки:   01000101  (Команда CMD_DIV с флагом BIT_REG)
Маска CMD_MASK:  00011111  (Фильтр младших 5 бит)
-------------------------
Результат (&):   00000101  (Число 5 -> это код команды CMD_DIV!)
```
Именно это делает макрос `#define CELL_OP(cell) ((cell) & (CMD_MASK))`. Он зануляет все верхние флаги, оставляя чистый Opcode.

---

#### 3. Побитовое НЕ (`~`) — Выделение флагов (Макрос `CELL_FLAGS`)
Чтобы, наоборот, отбросить саму команду и узнать только флаги, используется инверсия — **Побитовое НЕ (`~`)**.

Оператор `~` переворачивает все биты маски: `~CMD_MASK` превращает `00011111` в `11100000`. Теперь единицы стоят везде, кроме зоны кода команды.

```text
Пример ячейки:    01000101  (Команда CMD_DIV с флагом BIT_REG)
Инверсия (~MASK): 11100000  (Фильтр флагов)
--------------------------
Результат (&):    01000000  (Остался только чистый флаг BIT_REG!)
```
Этот процесс автоматизирован во втором макросе: `#define CELL_FLAGS(cell) ((cell) & (~(CMD_MASK)))`. Проверяя результат через `if (CELL_FLAGS(cell) & BIT_REG)`, процессор понимает, что дальше нужно читать номер регистра.

### Интерфейс управления архитектурой

Заголовочный файл `isa.h` помимо структур предоставляет набор глобальных функций для валидации байт-кода и трансляции инструкций. Эти функции связывают парсер ассемблера и рантайм виртуальной машины.

#### 1. Функции валидации (Runtime Validation)

*   `bool is_valid_opcode(code_t v);`
    *   **Зачем нужна:** Проверяет, валиден ли извлеченный код операции.
    *   **Как работает:** Отрезает маской флаги и проверяет, что полученное число лежит в границах `0 <= opcode < CMD_COUNT`. Используется процессором перед выполнением команды, чтобы избежать аварийного сбоя.
*   `bool isa_cell_ok(code_t cell);`
    *   **Зачем нужна:** Комплексная проверка всей ячейки байт-кода на валидность.
    *   **Как работает:** Проверяет не только сам `opcode`, но и корректность выставившихся битовых флагов (`flags`), сверяя их с эталонным массивом допустимых параметров `isa[...]` для данной команды.

#### 2. Функции парсинга и трансляции (Assembler Parsing)

*   `int operand_cells(int flags);`
    *   **Зачем нужна:** Возвращает количество ячеек памяти, которые занимают операнды (аргументы) *после* текущей команды.
    *   **Как работает:** Анализирует битовые флаги (`BIT_IMM`, `BIT_REG`, `BIT_MEM`). Помогает парсеру и процессору понять, на сколько ячеек нужно сдвинуть указатель инструкций (`PC`), чтобы прочитать аргументы.
*   `int find_command(const char* word);`
    *   **Зачем нужна:** Функция распознавания текстовых команд ассемблера.
    *   **Как работает:** Принимает строку (например, `"PUSH"`) и ищет её в массиве структур `isa`. Возвращает соответствующий `Opcode` (например, `1`) или `-1`, если команда не найдена.
*   `int find_register(const char* word);`
    *   **Зачем нужна:** Функция распознавания текстовых имен регистров.
    *   **Как работает:** Сравнивает строку (например, `"r2"`) со встроенным массивом строк `reg_names`. Возвращает индекс регистра (его физический номер от `0` до `REG_COUNT-1`) или `-1` при ошибке.
